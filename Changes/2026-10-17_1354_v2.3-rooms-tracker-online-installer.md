# ArchipelagoVic 2.3.0: room tabs, mini window, tracker, online hosting, YAML form, recap, updates, installer

**Date:** 2026-10-17 13:54 (local time)
**Request:** "Implement all of them, besides the phone alerts through a Discord webhook"

This applies every item on the improvement list except Discord phone alerts. The Oxygen Not Included DLL patch was not applied (see the last section).

## 1. Room tracker (archipelago.gg rooms)

**Where to use it:** paste an archipelago.gg room link (`https://archipelago.gg/room/<id>`) into the Server box or the new "Room page" field on the connect form.

**Connecting from a link:**
- ArchipelagoVic reads `/api/room_status/<id>` to find the room's port.
- If the room is asleep, it opens the room page in the background to wake it, then polls for up to 20 seconds.

**The Players tab while in a link room:**
- It shows real progress for every slot from `/api/static_tracker` and `/api/tracker`: a checks-done bar, items received, last active, and an "Open room page" link.
- It refreshes every 60 seconds.

**Room links in history:** recent rooms remember the link, so rejoining resolves the port again (ports change when a room restarts).

**main.js:** new `web:json` and `web:touch` handlers. They accept only https URLs whose path starts with `/api/` or `/room/`.

## 2. Generate and host on archipelago.gg

**Where:** Generate → "Or host it online" → "Generate and host on archipelago.gg".

**What happens:**
1. After a confirmation, every Players YAML is zipped and uploaded to `/api/generate`.
2. ArchipelagoVic polls `/api/status`, then opens `/new_room/<seed>` and reads the room's port.
3. Progress is shown as it goes.

**When it's ready:**
- "Join the room" opens it in Play.
- "Copy room link" copies the link for friends.
- The last online room is remembered.

**Custom worlds:** games from custom `.apworld` files are refused up front with a clear message, because the website can't generate them.

## 3. Mini window (always on top)

**Where:** Play → "Mini window".

**The window:**
- A small frameless window kept above borderless-fullscreen games (`setAlwaysOnTop(true, "screen-saver")`).
- Size and position are saved.

**What it shows:**
- Each room: status, game icon, checks done/total, ★ key items still out there, or Goal.
- The 8 latest items from other players across all rooms, with sender and age.

**Buttons:**
- "Open" brings the main window forward.
- "✕" or the Play button closes it.

**New files:** `renderer/mini.html` and `renderer/mini.js`.

## 4. YAML form editing

**Where:** "Edit" on a player YAML now opens a Form view. A Text toggle switches to the raw file.

**The form:**
- Slot name and description fields.
- A search box for options.
- Per option:
  - a dropdown of its choices, plus a number box for ranges (min/max taken from the template comments);
  - an inline field or a small text box for list/dict options;
  - the description, with "More".
- Options that are random by weight show the percentages and a "Pick one instead" button.

**How edits are written:** edits change only the weight lines inside the file, so comments, order and unknown content are kept exactly.

**Fallback:** files the form can't read (no `game:`, several games by weight, no options section) open in the text view with an explanation.

**Testing:** all 81 Archipelago 0.6.8 templates were parsed and edited, and stayed valid YAML with exactly one chosen value.

**New file:** `renderer/yamlform.js`.

## 5. Several rooms at once (tabs)

**How it's built:**
- Play is now a tab strip. Each room runs as its own `client.html` page in an iframe.
- Rooms send their status to the main window with postMessage.

**Tabs:**
- Each tab shows status, game icon, slot name, an unread count and ★ waiting items.
- "+ New room" opens another tab.
- ✕ closes a tab, asking first if it's connected.

**Other behavior:**
- Open rooms are reopened (pre-filled, not auto-connected) on the next start.
- "Join" from Home, Host, Generate or a link reuses the current tab if it isn't connected, otherwise it opens a new tab.
- The rail's Play badge shows how many rooms are connected.

**New file:** `renderer/client.html` (the room page).

## 6. Game recap

**Where:** "Recap" in a room header.

**What it shows:**
- Six tiles: checks done, items from others, key items received, items you sent out, hints about your items, time followed.
- A checks-over-time chart with a hover crosshair and readout. The axis shows times for same-day games and dates for longer ones.
- "Who sent you the most".
- Firsts: first key item, biggest helper, start time, goal time.

**Auto-open:** it opens by itself once per room when your slot reaches its goal.

## 7. Update checks

**Home → Updates:**
- Checks GitHub releases for Archipelago and for custom worlds with a known GitHub project. Oxygen Not Included → ShadowKitty42/ONI-Archipelago is preset.
- Shows the ArchipelagoVic and Archipelago versions.
- Results are cached for 12 hours. "Check now" forces a check, and a failed check is retried on the next visit instead of being cached.

**Worlds table:** a new "Updates" column with "Update" (downloads the `.apworld` from GitHub, inspects it, checks it's the same world, installs it) and "Set update source" (`owner/name`).

**Failures:** when GitHub can't be reached, it says so instead of claiming everything is up to date.

## 8. Installer

**App icon:** `renderer/icon.png` (512 px) and `renderer/icon.ico` (16–256 px). It's used for both windows, the installer and the uninstaller.

**package.json:**
- version 2.3.0;
- `build.win.icon`;
- NSIS installer and uninstaller icons;
- the portable file name is `ArchipelagoVic-<version>-portable.exe`.

**New `Build installer.cmd`:**
1. Checks for Node.
2. Installs dependencies if needed.
3. Runs `npm run dist`.
4. Opens `dist\`.

**Validated:** an unpacked Windows build was made with electron-builder 26.15.3 to check the config, and all app files were present in `app.asar`.

## Fixes found while testing

- **launcher.js:** the startup call ran before the new `Rooms` constant was initialised, which stopped the whole window from working ("Cannot access 'Rooms' before initialization"). The start block moved to the end of the file.
- **Recap:** a stray "null" line appeared above the tiles. Fixed, and "(1 items)" now reads "(1 item)".
- **Mini window:**
  - It showed no items when they arrived before the session's feed. It now uses the received-items list, so every item from other players counts.
  - It shows "No items from other players yet." when empty.
- **Room tab strip:** a vertical scrollbar appeared next to the tabs. Removed.
- **Online hosting:** the seed generated, but "opening a room failed", because Electron's fetch hides where a redirect goes. The `/new_room` redirect is now read with Node's fetch. Tested live: upload, then generation, then the room opened (`archipelago.gg:<port>`), and the Join button pre-filled the room tab.
- **Tracker API:** the response shapes (`room_status`, `static_tracker`, `tracker`) were checked against a live archipelago.gg room and match what the Players tab reads. The final WebSocket join to the website's room couldn't be run from the test machine (outgoing ports other than 443 are blocked there). It uses the same connect code as every other room.
- **Standalone page:** `tools/build-standalone.js` now builds `ArchipelagoClient.html` from `client.html` (the room page) and stops with an error if the source changed shape. In the browser version, a room link now explains that links need the app and asks for the server address instead.

## Not applied: Oxygen Not Included mod patch

**Status:** a patched `ArchipelagoNotIncluded.dll` that skips research checks while disconnected (instead of crashing) was prepared but not written. This environment's safety rules blocked writing the modified binary.

**The exact change (for v0.9.11, 1,314,304 bytes):**
- File offset `0x45AA`, 17 bytes, inside `Research_GetNextTech_Patch.Prefix`.
- Old: `18 8D 6D 00 00 01 25 16 1F 3C 9D 25 17 1F 3E 9D 26`
- New: `7E 49 00 00 04 2D 01 2A 02 7B 0A 01 00 0A 2D 01 2A`
- Meaning: if the mod isn't connected (`info` is null), or there's no active research, return early.

**Trade-off:** research finished while disconnected doesn't send its checks. The host can send them later with `/send_location`.
