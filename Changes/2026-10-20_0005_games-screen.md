# ArchipelagoVic 2.6.0: the Games screen and one-click Play (Game profiles, step 5)

**Date:** 2026-10-20 00:05 (local time)
**Request:** "Go on to step 5 (the Games screen with profile cards, the Play button and the progress list)." This is step 5 of Game profiles with a one-click Play button: a Profiles view with one profile per game, and a Play button with a visible progress list (pending / running / done / failed per step) and a clear plain-language error when a step fails. It keeps the existing UI style (styles.css tokens, themes) and wording.

Steps 1–4 (the patch helper, the `host.yaml` writer, profile checks and the Play flow) are now usable from the window, so this is **version 2.6.0**.

## What's new

**Games**, a new rail item under Play, and a "Play a BizHawk game" task on Home.

**A card for each game** shows:
- its icon (the existing `gameIcon`);
- a status line, one of "Checking…", "Ready to play.", "Ready. Choose this game's patch file when you press Play." or "2 things to fix before you can play.";
- EmuHawk, the ROM (named when ArchipelagoVic knows it, for example "Pokémon Red (US/Europe)"), the patch with its slot, and the last room;
- every problem in red under its line.

Play is turned off while EmuHawk or the ROM is wrong. Edit and Remove sit beside it, and Remove asks first. Cards are re-checked each time Games opens.

**Add a game / Edit:**
- **Fields:** EmuHawk.exe, the original ROM, the patch file (optional), the default room (optional) and the game. The file fields have Browse… buttons.
- **Live checks:** each field is checked as you fill it, and the problem appears under that field. The game is suggested from the ROM or patch. A line under EmuHawk says where to get BizHawk.
- **Saving keeps an unfinished game,** so it can be completed later. A toast says what's left, or that `host.yaml` now uses this EmuHawk and ROM too.

**The Play sheet:**
- **Fields:** the room (pre-filled with the last one used, or the profile's default), this session's patch file (with Browse…), and an optional room password.
- **A progress list of six steps:** Find the room → Check EmuHawk, the ROM and the patch → Patch the ROM → Start EmuHawk → Start the BizHawk Client → Open the room here.
  - Each step shows waiting (grey circle), running (spinner), done (green ✓) or failed (red ✕), with its own message.
  - If a step fails, the button becomes **Try again** and the note says "Nothing was left running. Fix what the red step says, then try again."
  - When all six are done: "You're in as VicTest. Play in EmuHawk; the activity feed is in the Play tab…". The room is already open in a Play tab.
- **While Play runs,** the fields, Cancel, ✕ and Escape are disabled, so it can't be closed halfway.
- **Keyboard:** Enter in a field presses Play.

**Styles:** only existing tokens (`--surface`, `--line`, `--ok`, `--bad`, `--sea`…) and the existing `apv-spin` animation. So it follows every theme, light and dark. There's no spinning when the system asks for reduced motion, and the cards stack on narrow windows.

**Problems found while testing:**
- **Dialogs never closed in the test copy.** A `<dialog>`'s close event never fires while its window is in the background, so the app's existing `sheet()` dialogs never closed there either. Bringing the test window to the front (DevTools `Page.bringToFront`) fixed it. This only affects a hidden test window, not the app.
- **One test could have written to your `host.yaml`.** My first Add-form test used the Blue ROM, which would have set `blue_rom_file` in your real `host.yaml` on save. It was changed to use the one-byte-changed copy, which never reaches `host.yaml`. The save didn't run in that first attempt, and `host.yaml` was confirmed unchanged after every run.
