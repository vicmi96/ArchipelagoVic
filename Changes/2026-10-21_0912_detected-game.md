# ArchipelagoVic 2.8.2: the game is detected, not typed

**Date:** 2026-10-21 09:12 (local time)
**Request:** A tester's feedback, passed on: "in the Game section, it defaulted to 'Pokemon Red and Blue' but greyed out like it wanted me to type in the field, so I typed 'Pokemon Red' … And it got very mad at me for not typing exactly 'Pokemon Red and Blue'. 'This patch is for Pokemon Red and Blue, but this profile is for Pokemon Red…' … the Game field should probably be either a dropdown field, autofill and not be a field." Followed by: "Can we fix it?"

## Why it happened

**The Game box was free text.** Its suggestion ("Pokemon Red and Blue") looked like a greyed-out default you had to type.

**The typed name was compared word for word** with the game name inside the patch. "Pokemon Red and Blue" is Archipelago's name for the whole game, and Red and Blue are two versions of it, so "Pokemon Red" didn't match.

**That comparison wasn't needed.** The ROM check already proves the patch and the ROM belong together, because the patch says exactly which ROM checksum it needs.

## What changed

- **No Game text box any more.** The Add/Edit form shows a read-only Game line instead:
  - **with a ROM ArchipelagoVic knows:** the game and the version, for example "Pokemon Red and Blue · Pokémon Red (US/Europe)";
  - **with a ROM it doesn't know:** the game from the patch file;
  - **before either is chosen:** "Found automatically from your ROM or patch file."
- **Where the game name comes from:** the patch, then a known ROM, then the name already stored in the profile (the last fallback, for games ArchipelagoVic can't recognise before a patch is chosen).
- **The "This patch is for X, but this profile is for Y" check is gone.** A patch for a different game or version is still caught, on the ROM line. For example, a Red patch with the Blue ROM gives "This is the Pokémon Blue (US/Europe) ROM, but this patch needs Pokémon Red (US/Europe). Choose your Pokémon Red ROM, or use a patch made for Pokémon Blue."
- **Profiles saved with a hand-typed name** (like the tester's "Pokemon Red") work straight away. The stored name is corrected to the detected one the first time the card is checked, and on every save.
- **The card heading, Play sheet and Edit title** use the detected name.

## Files

- **`main.js`:**
  - `checkProfile` takes the game from the patch or a known ROM (the stored name only as a fallback) and no longer compares names;
  - `saveProfile` always stores the detected name;
  - `profile:check` corrects a saved profile's name.
- **`renderer/launcher.js`:**
  - the Edit form's Game box became an `<output id="pf-game">` line, with the game's icon, name and ROM version;
  - the card heading, icon and Play sheet use the detected game.
- **`renderer/styles.css`:** `.profile-form output.detected`, using existing tokens.
- **`README.md`:** the BizHawk feature text says there's no game name to type.
- **`package.json`:** 2.8.2.
- **`ArchipelagoClient.html`:** rebuilt.

4. **The Edit form** has no Game text box; it has the Game line.
5. **The Edit form's Game line** reads "Pokemon Red and Blue · Pokémon Red (US/Europe)" (screenshot checked).

8. **A Red patch with the Blue ROM** is explained on the ROM line, and there's no patch-line error (screenshot checked).
9. **After switching to the Red ROM and saving,** the new profile is stored with game "Pokemon Red and Blue".
